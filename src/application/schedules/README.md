# 通用提醒

这是账号内的基础能力，不依赖外部日历。模型通过 zerolink-management MCP 的 `create_schedule`、`list_schedules` 和 `cancel_schedule` 工具管理计划；本地服务负责调度、保存、投递与状态恢复。每条计划配置触发时间、动作类型和文字内容；动作类型 `reminder` 发送固定提醒，`task` 将文字原样交给原会话的持久任务队列。两种动作均支持单次、每天和每周，以及分页查看和取消。

若希望到点运行任务，将 `kind` 改为 `task`，`text` 写为用户授权的任务要求，例如“汇总今天的新闻并发给我”。任务交给原会话的持久任务队列，按该会话的工作区和权限执行；内容由配置决定，不在调度器中写死业务流程。计划会绑定创建时的会话；若该会话随后被归档、删除或因切换底座而不可用，任务不会转移到别的会话。已提交的定时任务可能排队；计划的 `accepted` 仅表示队列已接受，不代表任务已完成。

重复提醒的 `create` 请求使用 `repeat` 代替 `at`：每天为 `{"frequency":"daily","time":"09:00","timeZone":"Asia/Shanghai"}`；每周还需 `"weekdays":[1,3,5]`，周一为 1，周日为 7。时间按指定 IANA 时区计算，夏令时不存在的本地时间跳过当天；重复的本地时间只发送一次。

每个账号私有目录的 `schedules.json` 记录计划。单次时间须为带时区的 ISO 8601 时间，必须晚于现在且不超过一年。调度器每 30 秒检查到期事项，每轮最多处理 10 条；因此触发可能略晚，离线期间到期的计划会在服务恢复并连上微信后尝试一次。触发前先持久化 `sending`；重启看到未完成的 `sending` 转为 `unknown`，不自动重试。重复计划只在本次发送或提交接口接受后推进到下一次；结果不确定时暂停，用户可核对后另建计划。提醒的 `accepted` 只表示微信发送接口接受，不代表用户已读。取消只能阻止尚未开始触发的计划，不能撤销已提交的任务。

管理 MCP 默认启用；禁用后模型不能创建、查看或取消计划，但已保存计划仍由账号本地服务触发。测试使用临时账号目录和模拟发送，不发送真实微信消息，也不运行真实定时任务。
