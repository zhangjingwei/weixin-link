# 通用提醒

这是账号内的基础能力，不属于可选集成插件，也不依赖外部日历。模型解析用户意图并调用 `src/interfaces/cli/schedule-cli.mjs`；调度、保存、投递与状态恢复由本地服务负责。每条计划配置触发时间、动作类型和文字内容；动作类型 `reminder` 发送固定提醒，`task` 将文字原样交给现有 Codex 任务队列。两种动作均支持单次、每天和每周，以及分页查看和取消。

本机 Codex 会话中的调用示例：

```sh
node src/interfaces/cli/schedule-cli.mjs <<'JSON'
{"action":"create","kind":"reminder","at":"2026-11-07T09:00:00+08:00","text":"开会"}
JSON
```

若希望到点运行 Codex，将 `kind` 改为 `task`，`text` 写为用户授权的任务要求，例如“汇总今天的新闻并发给我”。任务按原会话的工作区和权限执行，内容由配置决定，不在调度器中写死业务流程。计划会绑定创建时的会话；若该会话随后被归档或删除，任务不会转移到别的会话。已提交的定时任务由现有持久化队列处理，可能排队；计划的 `accepted` 仅表示队列已接受，不代表 Codex 已完成任务。

重复提醒的 `create` 请求使用 `repeat` 代替 `at`：每天为 `{"frequency":"daily","time":"09:00","timeZone":"Asia/Shanghai"}`；每周还需 `"weekdays":[1,3,5]`，周一为 1，周日为 7。时间按指定 IANA 时区计算，夏令时不存在的本地时间跳过当天；重复的本地时间只发送一次。

`CODEX_THREAD_ID` 必须指向当前运行的会话。命令通过本账号私有控制端点，由服务把会话映射到微信授权用户；请求中不接受收件人。查看传入 `{"action":"list"}`，可附 `offset`、`limit`（最多 10）；取消传入 `{"action":"cancel","id":"返回的提醒 ID"}`。不在命令行参数中传提醒正文。

每个账号私有目录的 `schedules.json` 记录计划。单次时间须为带时区的 ISO 8601 时间，必须晚于现在且不超过一年。调度器每 30 秒检查到期事项，每轮最多处理 10 条；因此触发可能略晚，离线期间到期的计划会在服务恢复并连上微信后尝试一次。触发前先持久化 `sending`；重启看到未完成的 `sending` 转为 `unknown`，不自动重试。重复计划只在本次发送或提交接口接受后推进到下一次；结果不确定时暂停，用户可核对后另建计划。提醒的 `accepted` 只表示微信发送接口接受，不代表用户已读。取消只能阻止尚未开始触发的计划，不能撤销已提交的 Codex 任务。

只给本机 Codex 注入定时能力说明。远程/容器底座和 Claude 暂不提供宿主定时命令。测试使用临时账号目录和模拟发送，不发送真实微信消息，也不运行真实定时任务。
