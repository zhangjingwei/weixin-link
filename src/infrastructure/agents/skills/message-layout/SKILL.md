# 消息排版

在组织微信回复时自动应用，不增加独立确认步骤或排版完成通知。保持原始含义、来源、重要限制和文件交付链接；不为了排版重写引用内容、删减成果或把推测变成事实。

## 按用途选择

- 普通交流直接用短段落；步骤、要点用列表，需要表达层级时再嵌套。不要把整个回复装进代码块。
- 需要用户复制转发的会议纪要、公告、邮件正文、命令等，将可直接使用的内容单独放在代码块中；自然语言使用 text，代码使用实际语言，结构化数据使用 json 等相应标签。解释、风险、操作指引和交付链接放在块外。
- 代码保留原有缩进、空行和特殊字符；不要为了屏幕换行插入会改变代码、URL、命令或数据的换行。自然语言正文避免超长单行；长代码行的可见截断不等于数据丢失。
- 网页使用名称清晰的链接；附件遵循既有交付约定，保持真实交付路径链接在代码块外，不能用排版替代实际文件交付。
- 比较数据少时用列表；表格会被发送层转换成文字记录，不依赖表格的列宽和对齐。大数据按需交付 CSV。
- 分隔线仅用于明显不同的长内容区段。小图标沿用方案讨论、交付助手的阶段标记，不额外添加「排版助手」标记，不逐段堆图标。

## 当前能力边界

当前客户端实测可显示列表、多层列表、网页链接、带或不带语言标签的代码块，代码高亮、缩进、空行、特殊字符和分隔线。text、json、Python 块已在测试中使用，截图可见代码块复制按钮。显示正常不证明复制结果完整；不把这次客户端结果推广到所有微信版本。

图片和 MP4 视频已实测可预览、打开、保存图片和播放视频。发送层先发送说明文字，再将媒体作为独立消息发送，正文链接显示为「名称〔附件〕」；不要承诺图片或视频嵌入正文指定位置。此次视频样例为 3 秒无声 H.264 MP4，不据此推断所有编码、大小和时长均受支持。

当前发送层会将标题、强调、引用、行内代码等转换为普通文字，不依赖这些样式表达关键信息。截图中的行内公式 E = mc^2 和独立公式的 LaTeX 命令没有真正数学渲染。简单公式可用 E = mc² 等 Unicode 文本；复杂公式需要可靠的文件或图片成果时按交付约定处理，不声称原生支持。勾选框交互尚未验证，不把它当成按钮。

用户要求特定格式或逐字引用时优先满足；用户正在测试消息格式时可发送待验证语法，并明确它尚未验证。输出前检查：可复制部分是否独立、说明是否在块外、代码围栏是否成对、链接是否仍能被发送层识别。
