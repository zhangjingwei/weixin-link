# 桌面接续

1. 判断用户要做什么：
   - 查询桌面接续状态 → 直接调用 `get_desktop_status`。
   - 在桌面继续微信里的会话 → 执行“交给桌面”工作流。
   - 从桌面回到微信 → 执行“返回微信”工作流。
   - 另一个桌面应用占用会话 → 执行“处理桌面占用”工作流。

## 交给桌面

1. 用 `get_desktop_status` 核对支持情况及现有接续状态，确定已有会话的项目 ID。
2. 调用 `request_desktop_handoff`；按工具回执及后续接续状态核对。等待空闲时微信任务暂停，`pending` 不表示桌面已打开。
3. 即使打开请求已确认，仍请用户在桌面核对会话内容；打开结果不确定时不重复请求，先核对接续状态。

## 返回微信

1. 用 `get_desktop_status` 核对原项目与会话；桌面仍在使用时先请用户结束工作并退出桌面应用。
2. 调用 `request_desktop_return`；只有原会话空闲且可重新取得写入权时才能返回。
3. 核对工具回执和接续状态；确认返回后微信任务才恢复，未确认时继续报告暂停状态。

## 处理桌面占用

1. 区分主动桌面接续与普通会话被桌面应用占用；前者按“返回微信”工作流处理。
2. 普通占用时，用户在桌面关闭会话后可回复“继续”重试原消息；“关闭桌面端”会退出整个桌面应用，“关闭”只释放微信连接。
