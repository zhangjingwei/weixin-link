# 统一入口：进展、控制、任务计划与材料交接

微信精确应急命令继续走原入口。普通请求由受限分类器识别，应用层校验归属、目标与任务身份，再调用原管理用例和持久队列。

## 已提供的日常操作

- “知识库做到哪了”：返回最近保留完成结果的原文节选和时间、当前任务、明确记录的阻碍及排队后续。没有计划记录时明确说明，不生成完成百分比或虚构后续计划。
- “停掉知识库当前任务”：绑定原任务和轮次，回执投递后才激活停止；请求成功不等于进程已经终止。
- “取消知识库的修复搜索任务”“修复搜索先做”：仅操作精确的 pending 任务。任务已起跑则拒绝，不打断运行任务。
- “取消知识库所有还没开始的任务”：原子取消本次查询快照中的任务；任何一项已经起跑则整批拒绝，不取消未来提交的任务。
- “知识库检查搜索，工具箱优化页面”：最多拆成5项，子任务必须取自用户原文，并保留完整请求作为范围和共同约束上下文。
- “先让知识库检查搜索，完成后再让工具箱优化页面”：依赖只能指向前面的计划项，前置执行未确认完成、取消、失败或结果未知时不放行后续任务。执行完成不等于业务验收通过。
- “把本条附件交给知识库分析”：先沿用原接收与预处理，再为明确的目标建立私有交接副本；不从历史消息猜测或读取附件。多项目场景只将材料交给明确的接收项目，不广播。
- “入口识别耗时多少”：查询分类阶段、耗时、回退和实际识别模型；未完成记录数不等于活跃进程数。

## 执行和恢复边界

同项目保持顺序，不同项目分别执行。优先级不能绕过依赖，也不能抢占已开始任务。队列在提交底座前原子标记 starting，取消和调整顺序只允许 pending；重启后的 starting 任务保留核对语义，不直接重放。

原始入站、分流决策、管理操作与任务队列共同提供幂等身份。部分多项目提交完成后中断，恢复时复用原操作及任务编号，不重复已提交的子任务。未确认投递不自动重发通知。

分类输出额外包含用户点名的项目名称；应用检查其来自用户原文并且与目录唯一匹配。未知项目或不一致目标转澄清，不能悄悄派给当前项目。模型仍可能误判，不能用小样本验收承诺全部自然语言表达均正确。

## 模型与性能

意图识别使用可用的 gpt-6.1-terra，中档推理、普通速度；不会继承项目的执行模型。Terra 不可用或固定第三方接入时回退原队列，不自动替换为其他模型。分类只接收精简的项目与任务摘要，完整原始请求仍交给执行链路。

受限进程按账号复用，模型列表缓存5分钟；每条请求使用独立 ephemeral 线程，不共享对话上下文。空闲60秒、32次识别、错误或关闭时回收进程并清理临时认证副本。插件、MCP、Shell、浏览器和多智能体被禁用，工具请求被拒绝。路由器没有直接执行项目工作的权限。

分类上下文采用单套步骤输出结构，避免重复描述单项/多项字段。只保留项目身份、名称、运行标记、队列摘要、必要澄清与本条材料说明；不传线程、运行任务正文和时间戳。完整用户原文不截断，项目目录不按关键词删减，同名/未知项目仍走澄清与应用校验。原任务及交付链路不使用这个精简副本。

## 材料和隐私

交接副本保存在账号数据目录的 attachment-handoffs，目录0700、文件0600，不进入源码仓库。只允许本条原接收目录中的文件，拒绝符号链接和来源越界，核对内容摘要。目标、原始消息和快照绑定，重试不覆盖已存在且内容不同的副本。

所有关联消费任务执行完成后开始7天保留期，启动及每小时检查到期副本；失败、未知或没有可确认消费记录时保留。这里只清理交接副本，原始收件和项目源文件不由此删除。设有容量上限，达到上限时明确失败。

## 验证

单元/集成测试覆盖任务身份、取消起跑竞态、原子批量取消、优先级与依赖、部分提交恢复、附件越界和七天清理、证据来源、隔离进程和缓存。

开发仓库可在明确授权下运行合成真实模型验收：

```sh
node src/tools/verify-entry-routing-live.mjs --live /private/report.json
```

默认 Terra、medium、普通速度；`--low` 对照低推理，`--fast` 对照 Fast 速度，`--model gpt-6-luna` 可显式对照 Luna，但不改变生产默认模型。工具仅分类合成文字，不调用项目执行工具、不发送微信消息。报告包括逐例结果、耗时及上游返回的 token 用量；这些 token 数不是订阅实际扣费。

本次先后测试中，旧 Luna low 为20/22；明确目标字段与 medium 组合为22/22，另外2项控制案例为2/2。Terra low 和 Luna medium 的同一组重点案例均为7/7。组合变化影响结果，不能把全部差异单独归因于模型或推理档；样本量也不足以推断总体准确率。尚未做真实微信端到端和其他平台人工验收。

Terra medium 的普通速度精简对照中，完整合成测试为23/24，未通过项是讨论主题与路由目标冲突后触发的多余澄清，没有提交任务。明确这条规则后，讨论、否定执行、简短肯定、未知/同名目标与澄清答复6项定向复测为6/6；没有将其表述为最终提示词已完整通过24项。

同一组24条合成输入的上游输入 token 从167,185降到158,954（约4.9%），普通速度中位耗时约6.0秒；基线使用Fast，不能把速度差异单独归因于上下文精简。最终规则说明另有少量增补，节省比例是该完整对照的实测值，不保证生产请求有固定降幅，也不是套餐实际扣费。每条隔离线程仍有底座固定开销，不通过截断原始任务来追求更大降幅。

2026-11-23 最终规则完整复测：Terra medium、普通速度的 24 项合成输入全部通过。此前一次复测为 23/24，局部禁止执行引用命令被误判为整条讨论；明确否定范围后重新跑完全部案例。真实使用部分由维护者在本轮确认验收无问题，不将该确认扩展为其他平台或全部自然语言表达均已验证。
