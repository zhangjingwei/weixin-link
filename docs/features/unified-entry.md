# 微信入口派单与执行器

用户选择 Codex 时使用系统安装的 CLI 和用户自己的 Codex 配置。服务从 PATH 查找可执行文件，也可以在服务停止时用 `node src/setup/agent.mjs configure codex --binary /绝对路径/codex` 指定。启动时检查 app-server 协议，系统 Codex 不可用时不会调用项目依赖中的 CLI。选择其他执行器沿用各自的原生会话与认证。

新会话没有默认执行器。未确认目标时，原消息留在本会话的持久队列，微信列出可用执行器。回复名称即可绑定并继续，停止会取消等待选择的消息。这条流程无需模型 Key。已绑定会话将“换成 Claude”等自然语言原样交给当前执行器。当前执行器理解请求后调用管理 MCP 的 request_agent_switch。仅切换时省略 text，提供后续请求时由新执行器接手。已有原生会话的追问、明确的管理命令、停止和恢复沿原链路执行。

在已绑定会话中说“帮我接入豆包”，当前智能体可调用 `list_agent_executors` 检查主机，再用 `request_agent_registration` 登记兼容的本机 CLI。注册后同账号的会话即可选择它。如果用户还要求“让豆包接着做”，再通过 `request_agent_switch` 交接当前会话。登录状态在建立原生会话时核对。

## 会话交接

通过 MCP 指定后续任务时，原执行器在 `request_agent_switch` 的 `text` 中保留用户请求，在 `handoff` 中填写目标，并按需要记录约束、关键决定及依据、已完成工作、验证方法、相关文件、未决问题和下一步。原执行器可通过 `evidenceTaskIds` 引用同一逻辑会话内已经结束的任务，包括更早或由其他执行器完成的任务。平台也纳入源任务记录中的直接前置任务和补充输入所接续的任务。平台检查归属，保留任务编号、轮次、状态和可用的文件索引。新执行器可按编号读取仍保留的任务结果。

只切换且没有提供交接说明时，平台从源原生会话最近一个有结果记录的任务提取原请求、回复摘录和文件索引。若没有匹配的记录，则只交接已有的会话信息。交接资料保存在账号会话状态中，等新执行器实际收到资料并完成该轮后清除。只切换、尚未开始工作时再换一次，会继续传递待用资料。服务重启后仍可接续。源执行器确认本轮正常结束后，接手的执行器在同一微信会话返回任务结果。源执行器可以没有最终文字回复。

## 管理操作边界

管理 MCP 的能力令牌绑定当前会话和 RPC 尝试，不接受模型提供的用户身份作为授权依据。服务端重新校验调用者、目标项目、任务身份与当前状态。写操作复用管理操作记录及 `DurableJobs` 队列；同项目保持顺序，结果返回原微信用户，不创建独立分类队列。

- 查询进展和结果时，以持久任务与已保存的完成证据为准；没有证据时不推断完成百分比。
- 停止、取消和调整优先级时，绑定明确的项目及任务。仅修改待执行任务；任务已起跑、取消或结果未知时保留相应状态。
- 跨项目转交保留原始请求及其授权范围，使用原任务身份去重。需要当前消息的附件时先完成接收和预处理，再为明确目标创建私有交接副本。
- 多项目任务的依赖只指向先前任务；前置任务执行完成不等于业务验收通过。失败、取消或结果未知时不放行依赖任务。

## 附件与隐私

附件交接副本保存在账号私有 `attachment-handoffs` 目录，拒绝符号链接和来源越界，核对文件内容。所有关联消费任务执行完成后开始七天保留期；失败、未知或没有可确认消费记录时保留。这里只清理交接副本，不删除原始收件或项目源文件。

## 验证边界

相关代码位于 `src/application/management/`、`src/interfaces/controllers/management-mcp-controller.mjs` 和 `src/application/tasks/`。使用与改动范围相关的管理、任务及附件测试验证行为；真实微信收发和跨平台服务验收需另行在授权的测试环境完成。
