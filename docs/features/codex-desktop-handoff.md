# 在桌面继续微信里的工作（实验功能）

目标是：在微信交代工作，回到同一台 Mac 后打开原会话继续处理，再回微信接着用。微信助手与个人 Codex 共用本地会话目录。桌面接续通过会话 ID 打开原对话。

## 使用条件

- macOS，安装在 `/Applications/ChatGPT.app` 或 `/Applications/Codex.app` 的桌面客户端。
- 使用 Codex 订阅登录；第一版不支持第三方模型接入。
- 一个微信账号仅有一个获授权的使用者。桌面能访问该账号的会话，因此不向多人共用的账号开放。
- 先完成桌面里原有的任务并退出客户端。打开结果是否正确，仍需实际界面验收。

默认关闭。在安装电脑，指定对应账号并通过原配置入口启用（开发版源码目录执行，JSON 走标准输入）：

```sh
WECHAT_ACCOUNT=default node src/setup/setup.mjs config-set desktop <<'JSON'
{"version":1,"enabled":true,"app":"ChatGPT"}
JSON
```

已有服务需要先升级到本开发版才具有相关工具；配置默认只影响对应账号。可用 `config-check desktop` 校验同样的 JSON；禁用时将 `enabled` 改为 `false`。禁用配置不会强行解除进行中的交接，也不会删除会话或关闭桌面。仍可在客户端关闭后请求返回微信。

## 怎么用

1. 在微信说“在桌面继续知识库项目”。项目必须已有原生会话。
2. 助手等待当前工作结束，再请求打开同一个原生会话。桌面期间，这个微信账号的新工作、升级重启及会话修改暂停（查询仍可用）；已经排队的任务保留，不会丢弃或自动重跑。
3. 在电脑检查会话名称、工作目录和聊天历史是否正确。当前仅确认打开请求是否返回，不能自动确认界面内容或侧边栏是否显示。
4. 完成桌面工作，正常退出客户端后，说“回到微信继续知识库项目”。后台程序也退出、原会话可读且空闲后才恢复微信执行。

打开失败或结果不确定时保持暂停，避免两边重复执行。不要连续重复打开；先关闭桌面，再查询交接状态或请求返回。等待打开时若回执丢失或服务重启，也不会自动重新打开；核对状态后返回微信再重新安排。长时间忙碌的请求可能到期，此时暂停标记仍保留，需要核对后返回。

## 实现和权限边界

- 应用层管理用例沿用 `managementOperations` 和 `desktopHandoff` 会话状态，MCP 回执后才激活打开操作；不新建任务数据库。
- 通过 macOS `open` 的环境参数让桌面使用该微信账号的 `CODEX_HOME` 和 `CODEX_SQLITE_HOME`，再用官方 `codex://threads/<id>` 定位原会话。桌面自身的其他偏好行为不在此协议保证范围内。
- 不复制 auth、rollout、个人全局数据库或配置，不篡改原生记录，不更改账号的会话存储位置。项目目录及桌面分组由原生客户端处理，逻辑项目名与桌面项目分组不是同一个目录映射表。
- 同机其他桌面实例或其应用包内后台进程存在时拒绝打开/返回。不会自动杀掉客户端、批准操作或停止用户在桌面的工作。
- 返回只使用原生 `thread/read` 核对原线程、目录和空闲状态，不启动模型、不重新执行任务。重新连接微信时使用原线程，因此桌面产生的新历史由原生恢复链路载入。桌面产生的任务不伪装成微信队列任务；微信保存的最近结果和进展不会因打开桌面自动更新，需要读取原生历史核对。
- 桌面应用是否尊重环境变量、如何筛选 `appServer` 来源，以及个人默认启动下是否显示，必须由对应版本的真实桌面验收确认。环境参数和深链接不是“同步已成功”的证据。

## 验证与尚未验收

自动测试覆盖默认关闭、请求归属、回执前不打开、等待空闲、队列暂停与恢复、未知打开及重启、重复请求、保存失败、线程/目录变更、已有桌面后台进程、只读返回和配置校验。

```sh
node --test tests/management/desktop-handoff.test.mjs
node src/tools/verify-management-native.mjs
node src/tools/verify-desktop-native.mjs
```

原生兼容检查只使用临时 HOME 和 CODEX_HOME，不登录、不启动模型轮次、不打开真实桌面。当前固定版本的两个原生客户端可以读取同一个持久线程；空白测试线程没有出现在显式原生列表中，因此该检查不证明桌面列表可见。现有有消息会话的列表、历史接续、桌面端运行、再回微信，以及第三方客户端兼容均需真实联调。

依据：[原生 App Server](https://learn.chatgpt.com/docs/app-server)、[桌面深链接](https://learn.chatgpt.com/docs/reference/commands#deep-links)。不修改原生客户端来绕过这些限制。
